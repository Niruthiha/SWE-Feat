## Task
**Extracting translatable messages with Sphinx's gettext builder**

In this Sphinx repository, extracting translatable messages with the gettext builder does not work:
parts of the code it relies on are missing. Make it work end to end, so that a user can run the
gettext builder on a project and get correct message template (.pot) files:

- every translatable message is recorded with each place it occurs: the source file, the line and
  a unique identifier for that occurrence. A message that occurs several times keeps all its
  locations. Occurrences without a unique identifier (replicated content, such as todo items) are
  ignored; a missing source is recorded as an empty path and a missing line as -1;
- the .pot files are produced from templates. The user's own template directories are searched
  first, in the order given, and Sphinx's built-in gettext templates are the fallback. Strings
  written into the file are escaped the way gettext needs: backslashes and quotes escaped and
  newlines turned into gettext continuation lines. Templates can ask for the location of a source
  file as a canonical path relative to the output directory.

Find out where in the codebase these pieces belong and implement them so that they fit the
rest of Sphinx. All dependencies are installed; do not install anything.

You are forbidden to access https://github.com/sphinx-doc/sphinx/.
